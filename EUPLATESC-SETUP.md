Activation checklist:

1. Confirm delivery timeframe, return address, and each carrier's shipping fee. Set the remaining public values and per-carrier variables on the preview deployment and rebuild it. The customer can choose each enabled courier in checkout; the choice and charge are verified server-side and saved with the order.
   The intended next choice is delivery to an address or to a named locker: FAN Courier home/FANbox and Sameday home/easybox, each with its own confirmed price. Do not expose a locker option until the customer can select a real locker from that carrier's current list, the store saves its provider ID and address with the order, and the carrier integration can use that ID to generate the AWB. Check each product's packed weight and dimensions against locker limits before offering it. The sample 2 kg, 30 × 30 × 10 cm parcel is not a guarantee for all products or orders. Never infer that locker delivery is cheaper without the actual carrier tariff.
2. Verify transactional email from the private order page. On 21 October, `SMTP_HOST=smtp.hostinger.com`, port 465 with TLS, `SMTP_USER=orders@estorehouse.ro`, `SMTP_FROM`, and `ORDER_NOTIFICATION_EMAIL` were added as Config variables to Preview only. `SMTP_PASS` and `STORE_ADMIN_TOKEN` were added as Secrets in Preview only; their values are not in this repository. On 22 October, the private SMTP check authenticated with Hostinger, the private page read the empty order list from Redis, and one owner-approved, fixed-recipient Preview email test visibly arrived in the `orders@estorehouse.ro` inbox. The Production SMTP values have not been verified. Redis is now the Preview order store; no Supabase migration is needed for this path.
3. Configure merchant ID and signing key. The checkout API rejects a browser origin different from `STORE_PUBLIC_URL`. Preview has Vercel Authentication: an unauthenticated POST to its callback returns `302` to Vercel sign-in, so EuPlătesc cannot deliver its server notification. If the owner authorizes a project-wide Vercel Automation Bypass secret, Vercel will provide `VERCEL_AUTOMATION_BYPASS_SECRET` to deployments. The Preview payment request will append that secret only to `ExtraData[silenturl]`; the callback itself still requires a valid EuPlătesc signature, matching order and amount. The private test now refuses to initiate without the bypass secret. Because the secret permits access to protected deployments throughout this project and appears in the URL sent to EuPlătesc, keep it out of logs, source, public pages, and messages; revoke it after testing if no longer needed. Production callbacks use the plain URL.
4. The owner completed the first Preview-only 1 RON payment for order `3bdd2402d889981e6d48cb3d` on 22 October. EuPlătesc emailed `orders@estorehouse.ro` that the bank approved it, but the original callback was blocked by Preview protection. The private admin page then queried EuPlătesc's documented `check_status` WebService by invoice ID, confirmed the approved, unrefunded 1.00 RON transaction, and reconciled this **test order only**. The private order list visibly shows `paid_review`; both store-generated emails (customer and merchant, addressed to the same test mailbox) arrived in `orders@estorehouse.ro`. A second test order, `cd49d48ab31188f6d1e795ca`, was created to prepare a new payment but was not paid; do not ship it and do not ask the owner to pay again for the first reconciliation. This validates the provider status query and email workflow, but the new signed server callback route still needs an authentic end-to-end notification before public checkout is enabled. Verify complaints and withdrawal receipts separately. No public test product is needed.
5. Obtain EuPlătesc's live approval and confirm the merchant's "Livrare permisă" rule before shipping. Set `EU_PLATESC_MODE=live`, production origin and secrets, and only then enable checkout in production.

The server prices the cart from reviewed catalog data, applies 10% to one cheapest unit at two or more items, then offers free shipping from 900 lei **after** discount. Browser-supplied prices are ignored. A signed approved callback moves the order to `paid_review`; the browser return alone never marks it paid. Shipment still requires green "Livrare permisă" status in EuPlătesc Manager.

The EuPlătesc receipt for the first test still displayed the old Strada Madrid address and `estorehouse2025@yahoo.com`, while the store uses the owner-confirmed Str. Târgului nr. 8 address and the new store mailboxes. Correct the merchant profile with EuPlătesc before live activation.
